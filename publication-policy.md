# Controlled public-release policy

## Default rule

Material is not public merely because it is useful, transparent, or stored in a
Microsoft workspace. Publication is a deliberate state transition.

## Release path

1. Classify the source item.
2. Identify copyright, license, confidentiality, privacy, security, and record
   constraints.
3. Create a public derivative or metadata record when the original cannot be
   released.
4. Review the release package for confidential data, private paths, credentials,
   and unsupported public claims.
5. Approve publication through an attributable human action.
6. Commit the public package to the appropriate organization repository.
7. Record version, provenance, limitations, license, and release date.

Automation may prepare and validate a release package but must not automatically
publish arbitrary SharePoint content. The publication bridge is one-way from an
approved staging area to GitHub; GitHub content must never overwrite restricted
records automatically.

## Transparent withholding

When useful and safe, publish an opaque record ID, public title or description,
restriction category, steward role, release status, and review date. Do not
publish internal URLs, access groups, sensitive filenames, personal data, or
detailed defensive controls.
